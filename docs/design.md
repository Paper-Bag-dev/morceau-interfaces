# morc design notes (11-08, frontend-design pass)

**Subject:** tiny, glanceable instruments floating over arbitrary pixels, for one person. Job: be read in under a second, then leave.
**One memorable thing per surface:** the hero numeral with a hairline needle (`stat`). Everything else stays quiet.

| token | value | why |
|---|---|---|
| accent | coral `14 90% 63%` (#F4764E) on Windows; **deep steel blue `glacier` `206 58% 48%` on macOS** (user, 11-10: tired of the orange) | one accent everywhere, pin/dismiss included; per platform in themes.json `platforms` |
| ink (floating text) | light, dark outline | subtitle style reads on bright and dark pages; dark text with a light halo did not |
| surfaces | warm dark `20 9% 9%` / warm paper `30 14% 96%` | flips against the page behind (anti-color), warm so it sits with the coral |
| display | Bahnschrift, width axis 92 | DIN-like numerals; ships with Windows, no network |
| body | Segoe UI Variable Text | legible small; clearly different from the display face |
| scale | 10.5 / 12 / 15 / 22 / 32 px | tabular figures on anything that changes |

**Rules:** no all-caps labels, no eyebrows, no middle-dot meta strings, no mono data labels, no arrows on buttons. Copy says what a button does
("Close", "Show 7-day report"), sentence case. Non-user-triggered motion only when it earns attention: the shimmer plays only on an urgent ask.
User-triggered motion (ripple, press-bounce, tick, hover lift, springs on arrival/exit) stays, because he asked for it and it shows what changed.
**Drag glow:** components glow orange, strongest on the biggest block, weaker as they get smaller; no outer ring.
**Tried and cut:** random/daily accent rotation (he wants one consistent coral); green/red yes-no (breaks the theme); shimmer on every primary button.

**Fun to read:** a report or recap is a few big numbers and one-line captions, never a text list. Prefer hero numerals over sentences, at most 3-4 short items, biggest type that fits, a little personality in the wording. If it reads like notes, cut it down or turn it into numbers.

**Responsive by default (rule, 11-08):** every card is padding plus flow, never fixed positions. Use flex/column/row flow and padding; no absolute positioning for content; the item sits inside the card, centred, with room round it. A component sizes itself from its own content and the box it is given (a chart measures its labels and widens, wraps or truncates with an ellipsis; it never lets text run past its edge). The window follows the content, and when a card grows on hover the window grows with it and the change is a smooth transition, not a jump. Tests: a long label, a narrow box and a hover must not clip anything.

**UI writing standard: never clip, always size within the container.** Default for every card, written by you or the background agent: content is padding plus flex flow, nothing absolute; an item is exactly as wide as its content (never padded out to a default width, which leaves a strip that the window cuts off); text that cannot fit wraps or ends in an ellipsis; long labels are measured and the component widens or shortens to fit; the window sizes to the content and hover growth is a smooth transition. Check a long label, a narrow box and a hover before calling it done.

**Group by kind:** numbers and text together in one card; each chart in its own separate card; never mixed, never one long vertical story, never one big blocker. Several small cards spread into free space, sized in between (charts importance 1.0, a text card 0.85 to 1.0).
**STRICT: every component is modular and controlled by a JSON file.** Layout in one JSON (`cache/seed/`); data, `align`, `importance`, `min_importance`, `region` and `ttl` are fields of its card JSON (`morc card`, `morc push`); nothing for one component lives in Python or Rust. A new knob is a field read for every card. Done only with: layout JSON, a short md in `docs/chips/`, an INDEX line. See docs/chips/INDEX.md.

**macOS glass (11-10):** the card plate sits on native Liquid Glass (`NSGlassEffectView`, dark appearance; `NSVisualEffectView` before macOS 26) placed by `src/platform/macos/glass.rs` under the web view at the rect the page reports (`layout.glass`). CSS `backdrop-filter` cannot blur other apps from a transparent WKWebView, so on Mac it is off and the page draws only a see-through dark tint, the grain and a light that eases toward the pointer (`plate.js`, `--mx/--my`). The backdrop sampling now works on Mac too (`sys::screen_average_rgb`, needs Screen Recording) and still picks the scheme, but the Mac `dark` scheme keeps dark surfaces: **mostly dark** (user, 11-10). Badges on Mac: white text, dark lens fill, black rim + grey inner line. Plate layers: dark grain, sparse light specks that slide with the pointer (the glint), pointer sheen, a lighter glow through the middle, the dark tint, the dark tint, and a 1px rim (light at the top, a faint accent down the sides). The pieces inside (list rows, badges) are dark pill-shaped lenses: a dark fill deepening to the edges via an inset shadow (follows the pill shape), a black outer rim with a thin LIGHT-BLUE line inside and a faint blue glow on hover; the middle is nearly clear (lens-center .16) and the dark edge reaches far in (lens-shadow 22px 6px), badge text white (user, 11-10); list rows see-through (.52) so the glow shows.

**Skins (11-10):** a skin is a named material set in `ui/themes.json` → `skins.<name>` (its colors join the base) and CSS keyed off `html[data-skin]`; sizes stay in `ui/tokens/*.json`. Layers, later wins: defaults → skin → `platforms.<os>`. `glass` is the first one (macOS turns it on: `platforms.mac.skin`); turn it on anywhere with `"skin": "glass"`. Never style a look with `html.os-mac`: that class is only for what truly needs the platform (dropping the CSS blur where native glass sits under the page).
**Even squircles (11-10):** rows, badges and buttons use a modest radius (`row-radius`, `btn-radius`, `badge-radius`) plus `corner-shape: squircle` where the engine has it, not full pills (user, 11-10).  list rows, badges and buttons are one line each with a minimum height and the same padding (tokens `list.json`, `button.json`); text that does not fit ends in an ellipsis and the full text is the tooltip by default (`item.tip` / `title` override it). Cards come out narrow and a little taller than wide (user, 11-10: "less wider, a tad longer"): truncate, do not widen. On the glass skin badges and buttons are FLAT accent pills, solid (`fill-alpha` 100%; 80% read dull over dark pages) (one solid color, no gradient, grain or glints: the user said the textured fill felt like old Android) with black text (`fill-ink`); rows stay dark lenses.

**Compact by default (11-10):** every card first shows at `limits.compact` (0.72) of its size, glows softly twice on arrival (`arrive-pulse-ms`), rows fade in one after another, and on hover the card grows smoothly to full size (window first, then the scale eases up; back down when the pointer leaves). `compact: 1` turns it off. Card titles are centered (token `title-align`). The glass skin uses the clear Liquid Glass style with light tints and nearly clear row centers, so what is behind shows through (user: "no light passes through").
**Compact = a teaser (11-10):** while squeezed (`#stage.compact`) lists show `compact-rows` rows and the next one fades out (`compact-peek`), tucked rows are not clickable, and the plate gets a solid accent edge with a rounder radius (`compact-border-w`, `compact-radius`, tokens/plate.json). Hover shows everything and drops the edge. **Hover without a click on macOS:** WKWebView only sees the pointer in the active app's key window, so the native hit test (window_style.rs) sends `Ev::Hover` and the page plays pointerenter/leave; Windows' WebView2 sees it by itself.
**Compact v2 (11-10):** compact 0.85 (a floor, so growth is not a big jump), 4 rows + a fading 5th, cards a little taller than wide. Squeezed: a light dark layer (`compact-dim` .16; darker lost the glass), a thin soft accent edge (`compact-border-w` 1.5px, `compact-edge-a` 70%) with rounder corners, no pin or close button (a pin nub on the edge was tried and cut). Growing is one smooth move: the native glass eases with the card (NSAnimationContext, and the page moves it ahead of a shrink with a `glass` message), the lists slide open (`reveal-ms`), the dark layer fades, the edge thins out (`morph-ms` 320). The accent-colored parts (buttons, badges, edge, lens lines and glow) all derive from `--accent`, so swapping the accent in themes.json recolors everything.
